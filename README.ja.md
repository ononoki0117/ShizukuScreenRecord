# Nizeo Client

`Nizeo Client` は、Meta Quest に Camera API が正式対応する以前に、Shizuku ベースの権限を利用して Android 端末上で画面キャプチャと録画を実現したプロジェクトです。

このアプリは単なる録画ツールではなく、当時のプラットフォーム制約を回避するのではなく、システム権限の流れを適切に活用してキャプチャパイプラインを構築した技術検証事例である点が重要です。

現在は、Shizuku を用いて画面録画を行い、録画結果をサーバーへアップロードしたうえで後続処理を進める Android アプリケーションとして整理されています。

本書は、日本企業への提案・エントリーを意識し、機能概要、実行フロー、必要権限、導入手順、ならびにプロジェクトの技術的背景を簡潔かつ明確に整理しています。

## プロジェクト背景

- Meta Quest 環境で Camera API の利用が制限されていた時期に、画面キャプチャ経路を確保するために開発されました。
- Shizuku を活用し、システム権限ベースのキャプチャフローを構成しました。
- 単なる機能実装ではなく、当時の技術制約下で動作可能な実用的な手段を確立した点に意義があります。

## 主な機能

- Shizuku 権限を利用した画面録画の実行
- 録画開始前の 3 秒カウントダウン表示
- 録画時間の選択 `10秒 / 15秒 / 20秒`
- 出力品質の選択 `Low / Middle / High`
- 対象範囲の選択 `ROOM / OBJECT`
- 変換スタイルの選択
- 録画ファイルのサーバーアップロードと後続処理の実行
- 処理完了後に結果 URL をブラウザで表示

## 動作フロー

1. アプリ起動後、ランチャー画面から案内ページまたはメイン画面へ移動します。
2. メイン画面で録画範囲、録画時間、品質、スタイルを選択します。
3. Shizuku 権限を確認したうえで録画を開始します。
4. 3 秒カウントダウン後に画面録画が始まります。
5. 録画終了後、ファイルをサーバーへアップロードします。
6. サーバー側の処理状況に応じて後続処理を行い、結果が準備でき次第ブラウザで表示します。

## 動作環境

- Android `8.0` 以上 `minSdk 28`
- `compileSdk 34`
- Shizuku に対応した環境
- ネットワーク接続可能な状態

## 必要な権限

アプリの機能上、以下の権限が必要です。

- `INTERNET`
- `POST_NOTIFICATIONS` `Android 13 以上`
- `READ_EXTERNAL_STORAGE`
- `WRITE_EXTERNAL_STORAGE`
- `MANAGE_EXTERNAL_STORAGE`

加えて、アプリ利用時には Shizuku 権限の許可が必要です。

## セットアップと実行

### 1. 開発環境の準備

- Android Studio の最新安定版をインストール
- Android SDK `34` を導入
- 実機またはエミュレータを用意
- Shizuku アプリおよび権限環境を準備

### 2. ビルド

```bash
./gradlew assembleDebug
```

### 3. 実行

- Android Studio から `Run` を実行する
- または生成された `debug APK` を端末へインストールする

### 4. 初回起動時の確認事項

- 通知権限の許可
- ストレージアクセス権限の許可
- Shizuku 権限の許可

## 使い方

1. ランチャー画面から案内ページまたはメイン画面へ移動します。
2. 必要な録画オプションを選択します。
3. `Start Record` ボタンを押して権限確認を行います。
4. カウントダウン終了後に録画が開始されます。
5. 録画終了後、自動的にアップロードと処理が進みます。

## プロジェクト構成

- `MainActivity` - 録画オプションの設定と開始処理
- `RecordingActivity` - カウントダウン後の録画開始
- `LoadingActivity` - アップロードおよびサーバー処理待機
- `LauncherActivity` - 初期導線と外部案内ページへの遷移
- `ScreenRecorder` - 録画制御
- `HttpClient` - サーバー通信

## 補足

- サーバー URL とアップロード先は `strings.xml` で管理されています。
- アプリは `cleartext traffic` を許可する設定になっています。
- 実運用・公開前には、サーバー設定、セキュリティポリシー、権限設計の再確認を推奨します。
